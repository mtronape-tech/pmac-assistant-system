# Requirements Document

## Introduction

Система помощника наладчика станков с ЧПУ (PMAC Assistant System) представляет собой интеллектуального помощника для наладчиков станков с ЧПУ на базе контроллера Turbo PMAC. Система построена на основе MCP (Model Context Protocol) сервера и веб-приложения, обеспечивает доступ к справочной информации, управление переменными PMAC, сбор и анализ данных, а также предоставление рекомендаций по настройке параметров.

Основная цель системы - повысить эффективность работы наладчиков станков с ЧПУ путем предоставления интеллектуального помощника, который может анализировать данные, предоставлять рекомендации и обеспечивать безопасное управление оборудованием.

## Requirements

### Requirement 1: MCP Server Core

**User Story:** Как разработчик системы, я хочу иметь основной MCP сервер для интеграции с ИИ моделями, чтобы обеспечить централизованное управление запросами и оптимизацию токенов.

#### Acceptance Criteria

1. WHEN система запускается THEN MCP сервер SHALL успешно инициализироваться и быть готовым к приему запросов
2. WHEN поступает запрос на переключение модели THEN система SHALL переключиться на указанную модель в течение 5 секунд
3. WHEN поступает запрос к ИИ модели THEN система SHALL маршрутизировать запрос к соответствующему модулю
4. WHEN система обрабатывает запросы THEN она SHALL кэшировать результаты для оптимизации токенов
5. IF модель недоступна THEN система SHALL переключиться на резервную модель автоматически

### Requirement 2: PMAC Control Module

**User Story:** Как наладчик станка, я хочу управлять переменными PMAC через веб-интерфейс, чтобы настраивать параметры станка безопасно и эффективно.

#### Acceptance Criteria

1. WHEN пользователь запрашивает чтение переменной PMAC THEN система SHALL вернуть текущее значение переменной
2. WHEN пользователь изменяет переменную PMAC THEN система SHALL валидировать значение перед записью
3. WHEN происходит запись переменной THEN система SHALL подтвердить успешную запись или вернуть ошибку
4. WHEN пользователь пытается изменить критическую переменную THEN система SHALL запросить дополнительное подтверждение
5. WHEN система настроена в режиме имитации THEN она SHALL работать с имитированными данными PMAC
6. WHEN система работает в режиме имитации THEN она SHALL сохранять все изменения в локальной базе данных

### Requirement 3: Knowledge Base Module

**User Story:** Как наладчик станка, я хочу получать объяснения и рекомендации от ИИ помощника на основе технической документации, чтобы быстро решать проблемы и изучать новые функции.

#### Acceptance Criteria

1. WHEN пользователь загружает документ THEN система SHALL проиндексировать его и сделать доступным для ИИ модели
2. WHEN пользователь задает вопрос THEN ИИ модель SHALL найти релевантную информацию в документации и дать объяснение
3. WHEN система обрабатывает документ THEN она SHALL разбить его на смысловые фрагменты (chunks) для лучшего понимания ИИ
4. WHEN ИИ отвечает на вопрос THEN система SHALL предоставить ссылки на источники информации в документации
5. WHEN система индексирует документ THEN она SHALL создать векторные представления (embeddings) для каждого фрагмента
6. WHEN система обрабатывает документы THEN она SHALL поддерживать форматы PDF, DOC, TXT, HTML
7. WHEN документ загружается THEN система SHALL извлечь метаданные (тип, категория, теги, версия)
8. WHEN пользователь просит рекомендации THEN ИИ SHALL анализировать документацию и текущие параметры системы
9. IF документ содержит изображения или диаграммы THEN система SHALL сохранить их и связать с текстовым содержимым

### Requirement 4: Data Collection Module

**User Story:** Как наладчик станка, я хочу собирать и анализировать данные с контроллера PMAC в реальном времени, чтобы отслеживать производительность и выявлять проблемы.

#### Acceptance Criteria

1. WHEN пользователь запускает сбор данных THEN система SHALL начать периодический опрос контроллера с заданной частотой
2. WHEN система собирает данные THEN она SHALL сохранять переменные PMAC (P, Q, I, M, L), координаты (x, y, z, a, b, c, u, v, w), состояние осей и системные параметры
3. WHEN происходит сбор данных THEN система SHALL фильтровать данные согласно настроенным параметрам (minChange, deadband)
4. WHEN система собирает данные THEN она SHALL сохранять их в базе данных временных рядов с отметками времени
5. WHEN система собирает данные THEN она SHALL применять настройки сжатия и агрегации данных
6. WHEN пользователь останавливает сбор данных THEN система SHALL корректно завершить процесс и сохранить все данные

### Requirement 5: Analytics Module

**User Story:** Как наладчик станка, я хочу анализировать собранные данные и строить графики, чтобы понимать тренды и принимать обоснованные решения.

#### Acceptance Criteria

1. WHEN пользователь запрашивает построение графика THEN система SHALL создать график с заданными параметрами
2. WHEN система анализирует данные THEN она SHALL выявлять тренды и аномалии автоматически
3. WHEN пользователь экспортирует данные THEN система SHALL предоставить файл в выбранном формате (PDF, Excel, CSV)
4. WHEN система обнаруживает аномалию THEN она SHALL создать отчет с описанием проблемы
5. IF данных недостаточно для анализа THEN система SHALL уведомить пользователя о необходимости дополнительных данных

### Requirement 6: Recommendation Module

**User Story:** Как наладчик станка, я хочу получать рекомендации по оптимизации параметров, чтобы улучшить производительность и предотвратить проблемы.

#### Acceptance Criteria

1. WHEN система анализирует текущие параметры THEN она SHALL генерировать рекомендации на основе исторических данных
2. WHEN генерируется рекомендация THEN система SHALL указать уровень уверенности и обоснование
3. WHEN пользователь применяет рекомендацию THEN система SHALL отследить результат для обучения
4. WHEN пользователь отклоняет рекомендацию THEN система SHALL учесть это в будущих рекомендациях
5. IF рекомендация критически важна THEN система SHALL выделить её как приоритетную

### Requirement 7: Web Interface

**User Story:** Как наладчик станка, я хочу иметь удобный веб-интерфейс для взаимодействия с системой, чтобы эффективно выполнять свои задачи.

#### Acceptance Criteria

1. WHEN пользователь открывает веб-интерфейс THEN система SHALL загрузиться и отобразить главную страницу
2. WHEN пользователь взаимодействует с чатом THEN система SHALL отвечать на запросы
3. WHEN пользователь управляет переменными PMAC THEN интерфейс SHALL предоставить интуитивно понятные элементы управления
4. WHEN система обновляет данные в реальном времени THEN интерфейс SHALL отображать изменения без перезагрузки страницы
5. IF происходит ошибка THEN интерфейс SHALL показать понятное сообщение об ошибке с предложениями по решению

### Requirement 8: Security and Safety

**User Story:** Как администратор системы, я хочу обеспечить безопасность управления станком, чтобы предотвратить несанкционированный доступ и опасные операции.

#### Acceptance Criteria

1. WHEN пользователь входит в систему THEN он SHALL пройти аутентификацию с использованием JWT токенов
2. WHEN пользователь пытается выполнить операцию THEN система SHALL проверить его права доступа
3. WHEN выполняется критическая операция THEN система SHALL требовать дополнительного подтверждения
4. WHEN происходит любая операция THEN система SHALL записать её в журнал аудита
5. IF обнаружена подозрительная активность THEN система SHALL заблокировать доступ и уведомить администратора

### Requirement 9: API Gateway

**User Story:** Как разработчик интеграций, я хочу иметь стандартизированный API для взаимодействия с системой, чтобы интегрировать её с другими системами.

#### Acceptance Criteria

1. WHEN поступает API запрос THEN система SHALL обработать его согласно OpenAPI спецификации
2. WHEN API возвращает ответ THEN он SHALL содержать корректные HTTP статус коды
3. WHEN происходит ошибка API THEN система SHALL вернуть структурированное сообщение об ошибке
4. WHEN система перегружена THEN API SHALL применить rate limiting для защиты от перегрузки
5. IF API запрос некорректен THEN система SHALL вернуть детальное описание ошибки валидации

### Requirement 10: Performance and Scalability

**User Story:** Как пользователь системы, я хочу, чтобы система работала быстро и стабильно даже при высокой нагрузке, чтобы не терять производительность в работе.

#### Acceptance Criteria

1. WHEN система обрабатывает запросы THEN она SHALL обеспечивать стабильную работу
2. WHEN система работает под нагрузкой THEN она SHALL поддерживать работу одного пользователя
3. WHEN происходит сбор данных THEN система SHALL обрабатывать большие объемы данных эффективно
4. WHEN система масштабируется THEN она SHALL поддерживать горизонтальное масштабирование
5. IF один из компонентов недоступен THEN система SHALL продолжить работу с ограниченной функциональностью
